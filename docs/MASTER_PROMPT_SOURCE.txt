Quiero que seas el ARQUITECTO PRINCIPAL, DESARROLLADOR PRINCIPAL y AGENTE DE IMPLEMENTACIÓN de este proyecto.

Tu misión es construir una aplicación web completa llamada provisionalmente:

AI COMMAND CENTER

El objetivo es crear un centro de mando multiagente donde yo, como usuario y moderador, pueda ver, controlar y coordinar varias IAs desde una sola página web.

NO QUIERO un simple mockup, una landing page ni una demostración estática.

Quiero una aplicación funcional, modular, mantenible y preparada para producción, empezando por un MVP completo y extensible.

==================================================
1. OBJETIVO GENERAL
==================================================

Construir una plataforma donde puedan coexistir:

- Claude
- GPT / Codex
- Gemini
- futuras IAs externas por API
- futuras IAs locales
- otros agentes compatibles con MCP
- herramientas externas conectadas mediante MCP

La plataforma debe permitir que:

1. Yo escriba una tarea.
2. El orquestador cree una tarea formal.
3. Una IA reciba la tarea.
4. Esa IA pueda analizarla y trabajar.
5. Esa IA pueda enviar un mensaje o solicitud a otra IA.
6. El orquestador entregue ese mensaje al agente correspondiente.
7. Las IAs puedan conversar entre sí.
8. Yo pueda observar esa conversación.
9. Yo pueda intervenir como moderador en cualquier momento.
10. Yo pueda pausar, cancelar, aprobar o redirigir una tarea.
11. Los agentes puedan trabajar con el mismo proyecto GitHub.
12. Los cambios queden asociados a tareas, commits y agentes.
13. GPT/Codex pueda auditar cambios, corregirlos y realizar commit/push cuando tenga autorización.
14. Claude sea principalmente el agente de implementación y trabajo pesado.
15. Gemini sea un agente opcional de investigación, segunda opinión y análisis adicional.
16. La arquitectura quede preparada para añadir otras IAs sin reescribir el sistema.

3. CONCEPTO FUNDAMENTAL
==================================================

No quiero que las IAs se llamen directamente entre sí.

Quiero:

AGENTE A
   ↓
ORQUESTADOR
   ↓
AGENTE B

El orquestador será la autoridad técnica que:

- crea tareas
- enruta mensajes
- mantiene estados
- mantiene contexto
- valida permisos
- registra eventos
- controla quién puede escribir
- controla quién puede hacer commit
- controla quién puede hacer push
- permite intervención humana
- mantiene historial

El agente nunca deberá obtener directamente las credenciales privadas de otro agente.

18. AGENT BRIDGE LOCAL
==================================================

IMPORTANTE.

Como Claude Code y Codex pueden estar trabajando localmente en la máquina, crear una arquitectura de AGENT BRIDGE.

Cada agente local tendrá un pequeño worker que:

- se autentica
- anuncia su presencia
- recibe tareas
- envía resultados
- envía estado
- mantiene heartbeat
- comunica errores
- puede acceder a su workspace local
- nunca expone directamente sus secretos

Ejemplo:

WEB
↓
ORCHESTRATOR
↓
AGENT BRIDGE
↓
CLAUDE CODE LOCAL

y:

WEB
↓
ORCHESTRATOR
↓
AGENT BRIDGE
↓
CODEX LOCAL

El backend nunca debe intentar manipular directamente el disco local del usuario.
